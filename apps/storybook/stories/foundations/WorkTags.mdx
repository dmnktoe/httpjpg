# Work Tags

The controlled vocabulary an editor picks work tags from. Three spellings of "TypeScript" are three
tags to a ranker and one to a human, so the list lives in code — `WORK_TAGS` in
`@httpjpg/storyblok-utils` — and Storyblok only ever offers these values.

Each tag has a **value** and a **label**, and they do different jobs:

- The **value** is what Storyblok stores and what the ranker keys on. It is stable and never
  renamed — renaming one orphans it on every story already carrying it.
- The **label** is what a visitor reads. Change it freely; nothing depends on its spelling.

## The vocabulary

## Adding a tag

1. Add it to `WORK_TAGS` in `packages/storyblok-utils/src/work-tags.ts`.
2. Run `pnpm --filter @httpjpg/storyblok-sync sync:datasources`.

The `tags` field on the `work` blok is a datasource-backed multi-select pointing at the
`work-tags` datasource, so the new tag shows up in the editor immediately after the sync.

## Removing a tag

Delete it from the catalog and sync. Stories still holding the value keep it in Storyblok, but
`resolveWorkTags` drops anything outside the vocabulary rather than rendering a raw slug — so
nothing leaks into the UI. That is what makes removal safe without a content migration.

## What reads them

```ts
import { resolveWorkTags, workTagLabels } from "@httpjpg/storyblok-utils";

// Values in, tags out — unknown values dropped, duplicates collapsed,
// ordered by group.
resolveWorkTags(["figma", "typescript", "made-up"]);
// → [{ value: "typescript", label: "TypeScript", group: "language" },
//    { value: "figma", label: "Figma", group: "tooling" }]

// Just the labels, for a card or a chip row.
workTagLabels(["ios", "swiftui"]);
// → ["SwiftUI", "iOS"]
```

- **Search** matches a whole tag above a substring of one, and finds `nextjs` for `Next.js`.
- **Related work** compares values, weighted by how rare each shared tag is in the corpus — two
  projects both tagged `web` say little on a site where everything is web.
- **Ask** grounds its answers in the labels, so the model sees `TypeScript`, not `typescript`.
